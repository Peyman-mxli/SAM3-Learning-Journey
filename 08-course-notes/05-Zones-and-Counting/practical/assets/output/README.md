# Output Assets — Zones and Counting

This directory contains the **generated video outputs** produced by the Zones and Counting practical.

Unlike the files inside `assets/input/`, these files are generated by the Python practical after processing the source video.

The outputs demonstrate different stages of spatial video analytics:

- Polygon occupancy
- Line-crossing counts
- Combined occupancy and flow

---

## Directory Structure

After running the complete practical, this directory can contain:

```text
output/
├── README.md
├── vehicles_polygon_zone.mp4
├── vehicles_line_zone.mp4
└── vehicles_combined.mp4
```

# Generated Outputs

The practical can produce three main output videos.

```text
vehicles_polygon_zone.mp4
```

Each video demonstrates a different part of the session.

---

# 1. Polygon Zone Output

The first output is:

```text
vehicles_polygon_zone.mp4
```

This video demonstrates **current occupancy analysis** using:

```python
sv.PolygonZone
```

The output can display:

- Detected vehicles
- Bounding boxes
- Persistent tracker IDs
- Polygon boundary
- Objects currently inside the polygon
- Current polygon occupancy

---

## Polygon Pipeline

The processing flow is:

```text
vehicles.mp4
     ↓
YOLO
     ↓
Detections
     ↓
ByteTrack
     ↓
Tracked Detections
     ↓
PolygonZone
     ↓
Zone Filtering
     ↓
Current Occupancy
     ↓
Annotation
     ↓
vehicles_polygon_zone.mp4
```

---

## Polygon Count

The current occupancy is available through:

```python
zone.current_count
```

This value represents the number of objects currently associated with the polygon.

For example:

```text
Frame 100 → 3 objects
Frame 101 → 4 objects
Frame 102 → 2 objects
```

The count can increase or decrease from frame to frame.

## Directional Counts

The accumulated counters are available through:

```python

line_zone.out_count
```

For example:

```text
Crossings Down: 15
Crossings Up: 9
```

Unlike polygon occupancy, these values represent crossing events accumulated throughout the video.

# Generating the Output

The final combined video can be created using:

```python
sv.process_video(
    source_path=INPUT_VIDEO,
    target_path=OUTPUT_COMBINED_VIDEO,
    callback=callback_combined,
    show_progress=True
)
```

For example:

```python
OUTPUT_COMBINED_VIDEO = (
    "assets/output/vehicles_combined.mp4"
)
```

The practical can define the output paths as constants:

```python
OUTPUT_POLYGON_VIDEO = (
```

# Creating the Output Directory

Before saving results, the practical should ensure the directory exists.

```python

    parents=True,
```

# Verifying the Results

After processing, each generated video should be reviewed.

Things to verify include:

- Are vehicles detected correctly?
- Are bounding boxes stable?
- Are tracker IDs reasonably consistent?
- Is the polygon in the correct location?
- Does the polygon count change correctly?
- Is the counting line positioned correctly?
- Are crossing events being detected?
- Are directional counters behaving as expected?
- Are all annotations visible?

---

# Debugging with Output Videos

Annotated videos are useful debugging tools.

For example, an incorrect count might be caused by:

```text
Incorrect detection
       ↓
Tracking problem
       ↓
Incorrect zone position
       ↓
Poor counting-line placement
       ↓
Unexpected output
```

Watching the generated video makes these problems easier to identify.

---

# Tracker ID Problems

If tracker IDs frequently change:

```text
ID:5 → ID:5 → ID:12
```

the system may have experienced an ID switch.

This can affect movement-based analytics.

The output video allows these tracking problems to be observed visually.

---

# Zone Position Problems

If the polygon is positioned incorrectly, objects may be counted in the wrong area.

For example:

```text
Expected:

Polygon → Left Lane

Actual:

Polygon → Part of Sidewalk
```

The annotated output immediately reveals the problem.

---

# Counting-Line Position Problems

A poorly positioned line may produce unreliable or less useful crossing measurements.

The line should generally be placed where:

- Objects clearly cross it
- Tracking is stable
- Objects are visible
- Occlusion is limited
- The line represents a meaningful boundary

# GitHub Considerations

Generated videos may be significantly larger than source-code files.

Before committing them, check their file sizes.

For large outputs, possible alternatives include:

- Compressing the video
- Creating a shorter demonstration clip
- Hosting the result externally
- Keeping only screenshots or GIF previews
- Documenting how to regenerate the video

The Python code should remain sufficient to reproduce the output.
