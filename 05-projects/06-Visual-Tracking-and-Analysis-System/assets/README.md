# Assets

This directory contains the visual input and output assets used by the **Visual Tracking and Analysis System**.

The assets are organized to keep original test media separate from results generated by the computer vision pipeline.

The current assets document the successfully tested image-based MVP integrating:

- YOLO object detection
- Supervision
- ByteTrack object tracking
- Meta SAM 3 segmentation
- Combined visualization

## Asset Organization

The project follows a simple rule:

```text
Original media   → assets/input/
Generated media  → assets/output/
```

Original input files should not be modified or overwritten by the processing pipeline.

This separation makes experiments easier to:

- reproduce
- compare
- debug
- document
- evaluate

---

## Naming Convention

Use descriptive filenames for assets.

### Recommended Image Names

```text
yolo_bus_test.jpg
pedestrian_detection_test.jpg
segmentation_test_01.jpg
crowded_scene_test.jpg
```

### Recommended Video Names

```text
tracking_test_01.mp4
pedestrian_sequence_01.mp4
occlusion_test_01.mp4
movement_test_01.mp4
```

### Recommended Output Names

```text
final_integrated_pipeline.jpg
tracked_analysis_output.mp4
segmentation_output.jpg
tracking_evaluation.png
```

Avoid generic names such as:

```text
image.jpg
test.jpg
video.mp4
output.jpg
```

Descriptive names make the repository easier to understand and maintain.

## Large Files

Large model files should not be stored in this directory.

For example, the SAM 3 checkpoint:

```text
sam3.pt
```

is several gigabytes in size and is downloaded separately from the official gated Hugging Face repository.

Model checkpoints should not be committed to GitHub.

---

## Security

Never store authentication credentials inside the assets directory.

Do not commit:

```text
HF_TOKEN
GITHUB_TOKEN
API keys
Passwords
Private credentials
```

Authentication information should be stored securely using environment variables or services such as **Google Colab Secrets**.
