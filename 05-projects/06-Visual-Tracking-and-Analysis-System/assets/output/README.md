```text
Frame 075 | Detections: 3 | Tracker IDs: [2, 1, 3]
```

---

## Tracking Interpretation

The video test demonstrates actual temporal tracking.

Tracker IDs:

```text
1
2
```

remained present throughout the sampled portions of the sequence.

Other IDs changed during the video:

```text
3
4
5
6
```

This occurred when detections disappeared, changed confidence, became partially visible, or were re-associated by the tracker.

This behavior is useful because it demonstrates an important difference between:

```text
Detection
```

and:

```text
Tracking
```

YOLO independently detects objects on each frame.

ByteTrack attempts to maintain the identity of those objects over time.

---

## Why Six Tracker IDs Were Observed

The value:

```text
Unique tracked objects: 6
```

does not necessarily mean six different physical objects were continuously visible.

It means ByteTrack created six tracker identities during the complete 75-frame sequence.

Tracker IDs can change when:

- an object temporarily loses detection
- confidence drops below a useful level
- an object moves partially outside the frame
- association between frames is interrupted
- a previously lost object is detected again

This is one of the behaviors that future tracking evaluation will measure more formally.

## H.264 Conversion

OpenCV initially generated the video using the `mp4v` codec.

Although OpenCV could read the resulting video, browser-based playback inside Google Colab was not reliable.

The output was therefore converted to:

```text
H.264
Pixel format: yuv420p
Container: MP4
```

using FFmpeg.

This produced a browser-compatible video that could be played successfully inside Google Colab.

---

## Important Video Engineering Lesson

A valid `.mp4` file is not automatically guaranteed to play correctly in every browser.

The container and video codec are separate concepts.

For example:

```text
MP4 container + mp4v codec
```

may work correctly in OpenCV while failing in a browser player.

The final workflow therefore uses:

```text
OpenCV processing
        |
        v
Temporary MP4
        |
        v
FFmpeg
        |
        v
H.264 / yuv420p
        |
        v
Browser-Compatible MP4
```

This improves portability of generated video results.

# Output Generation

## Image Output

The final integrated image is generated by the central pipeline implemented in:

[`../../src/pipeline.py`](../../src/pipeline.py)

The pipeline returns:

```python
{
    "detections": detections,
    "tracked_detections": tracked_detections,
    "segmentation": segmentation_output,
    "annotated_image": annotated_image
}
```

The annotated image can then be saved using OpenCV:

```python
cv2.imwrite(
    "assets/output/final_integrated_pipeline.jpg",
    final_result["annotated_image"]
)
```

---

## Video Output

The video workflow processes frames sequentially.

The fundamental processing loop is:

```python
while True:

    success, frame = capture.read()

    if not success:
        break

    detections = detector.detect(
        frame
    )

    tracked_detections = tracker.update(
        detections
    )

    annotated_frame = visualizer.annotate(
        image=frame,
        detections=tracked_detections,
        class_names=class_names
    )

    writer.write(
        annotated_frame
    )
```

The important difference from image processing is that the same ByteTrack instance remains active across the entire sequence.

This allows tracker state to persist between frames.
