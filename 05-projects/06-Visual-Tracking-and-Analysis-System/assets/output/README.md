---

## Understanding the Tracker IDs

The value:

```text
Unique tracked objects: 6
```

does not necessarily mean six different physical objects were continuously visible.

It means ByteTrack created six tracker identities during the complete 75-frame sequence.

A new tracker identity may appear when:

- an object temporarily loses detection
- detection confidence changes
- an object moves partially outside the frame
- association between frames is interrupted
- an object is detected again after being lost

This behavior provides useful information for future tracking evaluation.

# H.264 Conversion

Both generated video outputs required a final compatibility conversion.

OpenCV initially generated temporary video files using:

```text
mp4v
```

Although OpenCV could read these files, browser-based playback inside Google Colab was not reliable.

FFmpeg was therefore used to convert the videos to:

```text
Codec: H.264
Pixel format: yuv420p
Container: MP4
```

The final SAM 3 video conversion produced:

```text
Return code: 0
H.264 CONVERSION: SUCCESS

Output:
assets/output/sam3_tracking_output_01.mp4

Size:
approximately 1.27 MB
```

The converted video was then successfully previewed inside Google Colab.

---

# Important Video Engineering Lesson

A valid `.mp4` file is not automatically guaranteed to play correctly in every browser.

The container and codec are separate concepts.

For example:

```text
MP4 container
      +
mp4v codec
```

may work correctly with OpenCV while failing in a browser player.

The validated project workflow therefore uses:

```text
Computer Vision Processing
        |
        v
OpenCV VideoWriter
        |
        v
Temporary MP4
        |
        v
FFmpeg
        |
        v
H.264 / yuv420p
        |
        v
Browser-Compatible MP4
```

## Image Output

The integrated image pipeline is implemented in:

[`../../src/pipeline.py`](../../src/pipeline.py)

The pipeline returns:

```python
{
    "detections": detections,
    "tracked_detections": tracked_detections,
    "segmentation": segmentation_output,
    "annotated_image": annotated_image
}
```

---

## Video Output

For video processing, frames are processed sequentially.

The same pipeline instance remains active throughout the sequence so that ByteTrack can preserve temporal tracking state.

The fundamental workflow is:

```python
while True:

    success, frame = capture.read()

    if not success:
        break

    result = pipeline.process_image(
        image_bgr=frame,
        segmentation_prompt="person"
    )

    writer.write(
        result["annotated_image"]
    )
```

Before beginning a new video sequence, the tracker is reset:

```python
pipeline.reset_tracker()
```

This prevents tracker state from a previous image or video test from interfering with a new sequence.
