# Trajectory Summary

[`trajectory_summary.csv`](./trajectory_summary.csv)

This report summarizes the movement of each tracked object across the video.

Object center coordinates are calculated from bounding-box positions and compared between consecutive observations belonging to the same tracker ID.

For bounding box coordinates:

```text
(x1, y1, x2, y2)
```

the center position is calculated as:

```text
center_x = (x1 + x2) / 2
center_y = (y1 + y2) / 2
```

Movement between two consecutive observations is calculated using Euclidean distance:

```text
distance = sqrt(
    (center_x2 - center_x1)^2 +
    (center_y2 - center_y1)^2
)
```

The accumulated result provides an estimate of the total image-space movement for each tracked object.

Because this measurement is based on image coordinates, the resulting distance is expressed in **pixels**, not meters or another physical-world unit.

# Tracker Duration Chart

[`tracker_duration_chart.png`](./tracker_duration_chart.png)

This chart compares how long individual tracker IDs remained active during the processed video.

It provides a visual representation of tracker persistence and helps identify:

- Long-lived tracks
- Short-lived tracks
- Objects entering or leaving the scene
- Possible tracking interruptions
- Differences in object visibility duration

Tracker duration is derived from the first and last observations associated with each tracker ID.

# Movement Distance Chart

[`movement_distance_chart.png`](./movement_distance_chart.png)

This chart compares the accumulated image-space movement of tracked objects.

Movement is calculated from consecutive center-point positions belonging to each tracker ID.

The visualization helps identify:

- Objects with the greatest movement
- Objects that remained relatively stationary
- Differences in trajectory length
- Relative movement behavior between tracker IDs

Distances represent movement in image pixels and should not be interpreted as physical-world distance without camera calibration or additional spatial information.

---

# Confidence Chart

[`confidence_chart.png`](./confidence_chart.png)

This chart summarizes detection-confidence behavior across tracked objects.

Confidence values originate from the object detector and are stored with the corresponding tracking observations.

The visualization helps evaluate:

- Detection stability
- Average confidence behavior
- Differences between tracker IDs
- Potential low-confidence tracks
- Overall detector reliability during the processed sequence

Confidence analysis is useful when evaluating whether unstable tracking behavior may be associated with weaker detections.

# SQLite Persistence

The analytics reports are supported by structured tracking observations persisted in SQLite.

Instead of keeping tracking information only in memory during video processing, observations can be stored and queried after the processing pipeline finishes.

Persisted information can include:

- Frame number
- Tracker ID
- Class ID
- Class name
- Confidence
- Bounding-box coordinates
- Object center coordinates
- Temporal tracking information

This persistence layer makes it possible to generate reports independently from the original inference loop.

The workflow becomes:

```text
Video
  ↓
Object Detection
  ↓
ByteTrack
  ↓
SAM 3 Segmentation
  ↓
Tracking Observations
  ↓
SQLite Database
  ↓
Analytics Queries
  ↓
CSV Reports
  ↓
Visual Analytics
```

```text

      ↓

      ↓
YOLO Detection
      ↓
ByteTrack Tracking
      ↓
SAM 3 Segmentation
      ↓
Persistent Tracker IDs
      ↓
SQLite Persistence
      ↓
Tracker Analytics
      ↓
Trajectory Analytics
      ↓

```

This architecture separates inference from analysis.

The video-processing pipeline produces observations, while the reporting layer converts those observations into reusable evidence.

# Why These Reports Matter

A tracking system should provide more than an annotated video.

Visual output demonstrates that detection, tracking, and segmentation are functioning, but structured analytics make the results measurable.

The reports in this directory allow the project to answer questions such as:

- How many unique objects were tracked?
- How long did each tracker remain visible?
- How many observations were recorded?
- Which object classes appeared most frequently?
- Which trackers moved the greatest distance?
- How stable were detection confidence scores?
- What trajectory did each tracked object follow?
- Did tracker IDs remain persistent across frames?

This transforms the project from a visual demonstration into an **analysis system**.
