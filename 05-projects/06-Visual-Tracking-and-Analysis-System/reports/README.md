# Trajectory Summary

[`trajectory_summary.csv`](./trajectory_summary.csv)

This report summarizes the movement of each tracked object across the video.

Object center coordinates are calculated from bounding-box positions and compared between consecutive observations belonging to the same tracker ID.

For bounding-box coordinates:

```text
(x1, y1, x2, y2)
```

the center position is calculated as:

```text
center_x = (x1 + x2) / 2
center_y = (y1 + y2) / 2
```

Movement between two consecutive observations is calculated using Euclidean distance:

```text
distance = sqrt(
    (center_x2 - center_x1)^2 +
    (center_y2 - center_y1)^2
)
```

The accumulated result provides an estimate of the total image-space movement for each tracked object.

Because this measurement is based on image coordinates, the resulting distance is expressed in **pixels**, not meters or another physical-world unit.

For the current verified run:

```text
Total movement distance: 693.18 pixels
Maximum tracker movement: 203.37 pixels
Average movement per tracker: 115.53 pixels
Average step movement: 2.9883 pixels
```

# Analytics Source Data

The performance evaluation uses two existing reports as its primary source data:

```text
tracker_summary.csv
trajectory_summary.csv
```

This design allows system-level evaluation to operate independently from the original inference process.

The analytics workflow is therefore:

```text
Completed Tracking Results
        ↓
tracker_summary.csv
        +
trajectory_summary.csv
        ↓
performance_analysis.py
        ↓
System-Level Metrics
        ↓
performance_summary.csv
        ↓
performance_chart.png
```

This avoids unnecessarily rerunning computationally expensive computer-vision inference.

# SQLite Persistence

The broader analytics architecture supports structured tracking observations persisted in SQLite.

Instead of keeping tracking information only in memory during video processing, observations can be stored and queried after the processing pipeline finishes.

Persisted information can include:

- Frame number
- Tracker ID
- Class ID
- Class name
- Confidence
- Bounding-box coordinates
- Object center coordinates
- Temporal tracking information

This persistence architecture makes it possible to perform analytics independently from the original inference loop.

The original processing workflow is:

```text
Video
  ↓
Object Detection
  ↓
ByteTrack
  ↓
SAM 3 Segmentation
  ↓
Tracking Observations
  ↓
SQLite Persistence
  ↓
Analytics
  ↓
CSV Reports
  ↓
Visual Analytics
```

The SQLite database generated during the original Colab runtime is not required by the current performance-analysis module because the necessary aggregated tracking information has already been preserved in the CSV reports.
