# Ground Truth Evaluation

This directory contains the manually annotated ground-truth dataset used to evaluate the segmentation performance of the **Visual Tracking and Analysis System**.

The evaluation data was created from representative frames extracted from the two video-processing sessions used in Project 06.

---

## Purpose

The purpose of this evaluation dataset is to provide reliable reference annotations that can be compared against model predictions.

These annotations allow the project to measure segmentation quality using metrics such as:

- Intersection over Union (IoU)
- Dice coefficient
- Precision
- Recall
- False positives
- False negatives
- Detection omissions

The results will help document where the computer vision pipeline performs correctly and where it fails.

---

## Dataset

A total of **20 evaluation frames** were selected.

### Session 001

10 frames were extracted from:

`session_001`

These frames contain people recorded in a street environment with variations in:

- Position
- Movement
- Partial visibility
- Scale
- Occlusion

### Session 002

10 frames were extracted from:

`session_002`

These frames contain pedestrians in a busy urban intersection with more challenging conditions including:

- Multiple people
- Small objects
- Greater distance from the camera
- Crowded scenes
- Partial occlusion
- Significant changes in object scale

## Ground-Truth Annotation

The selected evaluation frames were uploaded to **Roboflow** and manually reviewed using an **Instance Segmentation** project.

Project name:

`Project-06-Evaluation`

The annotation class used for the evaluation is:

`person`

Each visible person was annotated individually using segmentation polygons.

The polygons were created around the visible shape of each person instead of using only bounding boxes.

This produces pixel-level reference masks suitable for segmentation evaluation.

---

## Annotation Workflow

The ground-truth preparation workflow was:

1. Process the original videos through the Visual Tracking and Analysis System.
2. Select representative frames from Session 001 and Session 002.
3. Save 10 evaluation frames from each session.
4. Upload the 20 frames to Roboflow.
5. Create an Instance Segmentation project.
6. Annotate visible people using polygon masks.
7. Review the annotations.
8. Export the completed dataset using **COCO Segmentation** format.

---

## Export Format

The annotations were exported from Roboflow using:

**COCO Segmentation**

The export contains:

- 20 images
- Instance segmentation annotations
- Polygon coordinates
- Class information
- COCO-compatible JSON annotation data

The exported annotation file is named:

`_annotations.coco.json`

This format allows the ground-truth masks to be loaded programmatically in Python and compared against predictions generated by the computer vision pipeline.

---

## Why COCO Segmentation

COCO Segmentation was selected because it provides structured polygon annotations that can be converted into binary masks.

These masks can then be compared against predicted segmentation masks.

For each object:

```text
Ground Truth Mask
        │
        ▼
Predicted Mask
        │
        ▼
Mask Comparison
        │
        ├── IoU
        ├── Dice
        ├── Precision
        └── Recall
```

This creates a reproducible evaluation pipeline instead of relying only on visual inspection.

---

## Evaluation Strategy

The ground-truth dataset will be compared against predictions produced by the project pipeline.

The evaluation process will measure:

### Intersection over Union

IoU measures the overlap between the predicted segmentation mask and the ground-truth mask.

```text
IoU = Intersection / Union
```

A higher IoU indicates stronger agreement between the prediction and the manually annotated reference.

---

### Dice Coefficient

The Dice coefficient measures similarity between two segmentation masks.

```text
Dice = 2 × Intersection / (Prediction Area + Ground Truth Area)
```

A value closer to `1.0` represents stronger segmentation agreement.

---

### Precision

Precision measures how many predicted positive pixels correspond to the ground-truth object.

```text
Precision = TP / (TP + FP)
```

---

### Recall

Recall measures how much of the ground-truth object was successfully detected.

```text
Recall = TP / (TP + FN)
```

## Environmental Condition Evaluation

Project 06 now includes a dedicated evaluator for the official guiding question:

> How do variations in lighting and occlusion affect object-tracking accuracy in recorded videos?

Files:

- [`environmental_condition_analysis.py`](./environmental_condition_analysis.py)
- [`environmental_conditions_template.csv`](./environmental_conditions_template.csv)
- [MVP Completion Matrix](../docs/MVP-COMPLETION-MATRIX.md)

The evaluator calculates condition-level **precision, recall, F1, ID-switch rate, and average confidence** from real labeled observations and exports reproducible CSV summaries and a comparison chart.

It deliberately refuses to invent condition results. To use it, copy the template to `environmental_conditions.csv`, record measured lighting/occlusion trials, and run:

```bash
python evaluation/environmental_condition_analysis.py
```

Generated outputs:

```text
reports/environmental_condition_results.csv
reports/lighting_condition_summary.csv
reports/occlusion_condition_summary.csv
reports/environmental_condition_chart.png
```
