# Object Tracking Assets

This directory contains the input and output assets used by the **Object Tracking with YOLO, Supervision, and ByteTrack** project.

The assets are separated into two directories:

```text
assets/
│
├── input/
│   └── vehicles.mp4
│
└── output/
    └── tracked_vehicles.mp4
```

---

## Input Directory

The input directory contains the original video used by the tracking pipeline.

```text
assets/input/
```

The expected input file is:

```text
vehicles.mp4
```

Full path:

```text
assets/input/vehicles.mp4
```

---

## Sample Video

The project uses a vehicle video containing moving objects that can be detected and tracked across consecutive frames.

The sample video used in the lesson is available from Roboflow:

[Supervision Vehicle Tracking Video](https://media.roboflow.com/supervision/video-examples/vehicles.mp4)

If the input video does not exist, the project script automatically downloads it.

The download configuration is:

```python
VIDEO_URL = (
    "https://media.roboflow.com/"
    "supervision/video-examples/vehicles.mp4"
)
```

and:

```python
INPUT_VIDEO = "assets/input/vehicles.mp4"
```

---

## Why Use a Video?

Object tracking requires multiple consecutive frames.

An image contains information from only one moment:

```text
Image
  ↓
Detection
```

A video provides a sequence:

```text
Frame 1
   ↓
Frame 2
   ↓
Frame 3
   ↓
Frame 4
```

This allows ByteTrack to associate detections between frames.

---

## Output Video

The output video is generated by:

```text
object_tracking_pipeline.py
```

The script processes the original video frame by frame.

The output contains:

- Bounding boxes
- Object class names
- Persistent tracker IDs
- Frame visibility counts
- Estimated visible time
- Object trajectories
- Current unique tracker count

---

## Example Tracking Label

A tracked object may display a label such as:

```text
car #5 | 42f | 1.40s
```

This contains several pieces of information.

### Object Class

```text
car
```

This comes from the YOLO object detector.

### Tracker ID

```text
#5
```

This is assigned by ByteTrack.

### Frames Visible

```text
42f
```

This means the tracker ID has appeared in:

```text
42 processed frames
```

### Estimated Visible Time

```text
1.40s
```

This is calculated using:

```text
frames visible
──────────────
video FPS
```

## Input vs. Output

The original input should remain unchanged.

```text
INPUT

assets/input/vehicles.mp4
```

The project creates a separate processed video:

```text
OUTPUT

assets/output/tracked_vehicles.mp4
```

This keeps the original source video separate from generated results.

## Automatic Directory Creation

The project automatically creates the required directories:

```python
Path("assets/input").mkdir(
    parents=True,
    exist_ok=True
)

Path("assets/output").mkdir(
    parents=True,
    exist_ok=True
)
```

Therefore, the directory structure can be created automatically when the project runs.

---

## Automatic Video Download

If:

```text
assets/input/vehicles.mp4
```

does not exist, the project downloads the sample video automatically.

The script checks:

```python
if not Path(INPUT_VIDEO).exists():
```

and downloads the video using:

```python
urllib.request.urlretrieve(
    VIDEO_URL,
    INPUT_VIDEO
)
```

## GitHub Considerations

Video files can be significantly larger than source-code files.

Before committing generated videos, check their size.

GitHub repositories generally work better when large generated assets are kept to a minimum.

The important reproducible parts of this project are:

```text
README.md
object_tracking_pipeline.py
assets/README.md
```

The input video can be downloaded automatically by the script.

The output video can also be regenerated by running the project.

## Reproducing the Output

To reproduce the output video, run:

```bash
python object_tracking_pipeline.py
```

The project will:

```text
Check directories
      ↓
Check input video
      ↓
Download video if necessary
      ↓
Load YOLO
      ↓
Create ByteTrack
      ↓
Process video
      ↓
Generate tracking annotations
      ↓
Calculate tracking analytics
      ↓
Save output video
```
